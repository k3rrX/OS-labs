## 3. Реализация

### 3.1 Алгоритм TimSort
Алгоритм сочетает сортировку вставками для малых подмассивов ("ранов") и слияние с галопированием для больших последовательностей.

**Ключевые этапы:**
1. Разделение массива на "раны" минимального размера (MIN_MERGE = 32)
2. Сортировка каждого "рана" алгоритмом вставок
3. Слияние "ранов" с использованием галопирующего поиска
4. Поддержка инвариантов стека для оптимального порядка слияний

### 3.2 Многопоточная модификация
```c
// Интеллектуальный выбор режима
if (n < MIN_PARALLEL_SIZE || max_threads == 1) {
    // Однопоточный режим для малых массивов
    timsort_single(arr, n);
} else {
    // Параллельный режим
    timsort_parallel(arr, n, max_threads);
}
3.3 Структура программы
Основной поток
    ├── Разделение массива на N частей
    ├── Создание N рабочих потоков
    │   ├── Поток 1: TimSort своей части
    │   ├── Поток 2: TimSort своей части
    │   └── ...
    ├── Ожидание завершения всех потоков
    └── Финальное слияние отсортированных частей
3.4 Системные вызовы
pthread_create() / pthread_join() - управление потоками

clock_gettime() - замер времени выполнения

get_nprocs() - получение количества ядер CPU

system("ps -T -p PID") - демонстрация потоков

5. Анализ результатов
5.1 Ключевые наблюдения
1. Суперлинейное ускорение (6.20x при 100k):

Разделение данных между потоками уменьшает размер рабочего множества

Данные помещаются в кэш процессора (L2/L3)

Уменьшение промахов кэша и обращений к оперативной памяти

Эффект "скрытого параллелизма" современных CPU

2. Оптимальное количество потоков:

Для массивов 100k-500k: 4 потока

Для массивов >1M: 4-8 потоков

Более 8 потоков нецелесообразно из-за накладных расходов

3. Зависимость от размера массива:

< 50k: многопоточность неэффективна (накладные расходы)

50k-200k: максимальное ускорение (данные в кэше)

200k: линейное ускорение с насыщением

5.2 Объяснение аномалий
Замедление при 2 потоках на 500k (0.94x):

Неравномерное распределение нагрузки

Конкуренция за доступ к общей памяти

Накладные расходы на синхронизацию превышают выгоду

Снижение эффективности при 8 потоках:

Гипертрейдинг дает меньший прирост чем реальные ядра

Увеличение накладных расходов на слияние

Конкуренция за системные ресурсы
